### 1. Implementation Summary

#### [`apps/ops/services.py`](file:///c:/Users/USER/Documents/INTERN/Project/Volunteer%20HR%20Management/python%20stack/apps/ops/services.py)

- **`acknowledge_onboarding(user, event, method="app_tick") -> OnboardingAcknowledgment`**:
  - Validates active user account with `ensure_active_account(user)`.
  - Atomically creates or updates `OnboardingAcknowledgment` for the current `event.onboarding_version`.
  - Records an append-only audit log entry.
- **`check_in(actor, event, user=None, method="qr_scan", qr_token=None, target_user=None) -> Attendance`**:
  - Enforces event state: `event.status == EVENT_ACTIVE` (raises `InvalidStateError` otherwise).
  - Verifies volunteer has an active assignment for the event (`status__in=ACTIVE_ASSIGNMENT_STATUSES`).
  - Checks onboarding requirement: If `event.require_onboarding_ack=True`, requires a matching acknowledgment for `event.onboarding_version` (raises `OnboardingRequiredError`).
  - Authorization & Method check:
    - Volunteer self check-in: requires `method="qr_scan"` with a valid check-in `QrToken`.
    - Coordinator / Admin check-in: calls `ensure_event_manager(actor, event)`.
  - Idempotent: If volunteer is already checked in, returns the existing attendance record.
  - Updates or creates `Attendance(status="checked_in", checkin_at=now, method=method)`.
- **`check_out(actor, event, user=None, target_user=None) -> Attendance`**:
  - Requires attendance to be in `checked_in` status (raises `InvalidStateError` if not).
  - Updates `checkout_at = timezone.now()`.
- **`mark_absent(actor, event, user=None, target_user=None) -> Attendance`**:
  - Requires manager permission (`ensure_event_manager`).
  - Disallows marking absent if attendance is already `checked_in` or `completed`.
  - Sets `attendance.status = "absent"`.
- **`submit_feedback(user, event, direction, target_user=None, score=None, tags=None, comment="") -> Feedback`**:
  - Event state check: `event.status == EVENT_COMPLETED` (raises `InvalidStateError`).
  - Score check: required and bounded within `1 <= score <= 5`.
  - Role-based routing:
    - `coordinator_to_volunteer`: Requires `is_event_manager(user, event)`, `target_user` is required and must have had an active assignment in the event.
    - `volunteer_to_event`: Volunteer must have participated in the event; `target_user` is forced to `None`.
    - `volunteer_to_coordinator`: Volunteer must have participated in the event; `target_user` is forced to `event.coordinator`.
  - Duplicate feedback check: Prevents duplicate feedback across `(event, rater_user, direction, target_user)`.
