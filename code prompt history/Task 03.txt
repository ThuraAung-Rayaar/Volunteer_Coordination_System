### Files Created & Configured

#### 1. [`apps/common/permissions.py`](file:///c:/Users/USER/Documents/INTERN/Project/Volunteer%20HR%20Management/python%20stack/apps/common/permissions.py)
- **Role Predicates**:
  - `is_admin(user) -> bool`: Evaluates `is_admin` or `is_superuser`.
  - `is_approved_coordinator(user) -> bool`: Evaluates `coordinator_profile.status == COORDINATOR_APPROVED`.
  - `is_event_manager(user, event) -> bool`: Evaluates if user is an admin or matches `event.coordinator_id`.
- **Domain Guard Functions** (used in service layer):
  - `ensure_active_account(user)`: Validates authentication, rejects `closed` accounts with `AccountClosedError`, and rejects active/future `blocked` accounts with `AccountBlockedError` (automatically treating expired blocks as unblocked).
  - `ensure_admin(user)`: Chains `ensure_active_account` and raises `PermissionDeniedError` if not admin.
  - `ensure_approved_coordinator(user)`: Chains `ensure_active_account` and raises `PermissionDeniedError` if not an approved coordinator.
  - `ensure_event_manager(user, event)`: Chains `ensure_active_account` and raises `PermissionDeniedError` if user is neither event coordinator nor admin.
- **DRF Permission Classes** (used on ViewSets/API views):
  - `IsActiveAccount`
  - `IsAdminRole`
  - `IsApprovedCoordinatorRole`

#### 2. [`apps/common/tests/test_permissions.py`](file:///c:/Users/USER/Documents/INTERN/Project/Volunteer%20HR%20Management/python%20stack/apps/common/tests/test_permissions.py)

- `test_ensure_event_manager_checks_ownership`: Verifies coordinator ownership and admin bypass.
- `test_ensure_approved_coordinator`: Verifies approval gatekeeping across coordinator statuses.
- `test_ensure_admin`: Verifies staff/superuser privilege enforcement.
- `test_drf_permission_classes`: Verifies DRF request permission bridge behavior.
