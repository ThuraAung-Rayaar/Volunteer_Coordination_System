OTP rules:
OTP expires in 300 seconds.
Max attempts: 5.
Store only code_hash.
In DEBUG only, settings.DEV_FIXED_OTP may be accepted.
If account is blocked, reject login.
If account is closed, reject login.
First successful OTP creates user.
Verification image rules:
Convert uploaded image to JPEG.
Strip EXIF.
Store in private storage, not public MEDIA URL.
Save file SHA-256.
Set old images of same image_type to is_current=False.
Set new image is_current=True.
Set user verification_status = pending


Verification status recomputation:
If any current image is rejected:
    verification_status = rejected
Else if current approved mock_selfie exists
and current approved id_license or driver_license exists:
    verification_status = verified
Else if any current image is pending:
    verification_status = pending
Else:
    verification_status = none

Coordinator approval rule:
Admin can approve coordinator only if user.verification_status == verified.

Event lifecycle:
draft -> published -> active -> completed
published -> cancelled
active -> cancelled

Publish rules:
Actor must be event coordinator or admin.
Event must be draft.
Event must have at least one post.
Complete rules:
Event must be active.
Set event status to completed.
Set confirmed assignments to completed.
Set checked-in attendance rows to completed.
Cancel rules:
Event must be published or active.
Cancel active assignments.
Set attendance expected rows to absent only if not checked in.
Application rules:
Event must be visible and status published or active.
Application deadline must not have passed.
User must be active.
User must not already have active application for same event.
If source is qr_walkin, QR token is required.
Store conditions_snapshot containing:
meals_provided
lodging_provided
travel_support_provided
compensation_kind
compensation_note
onboarding_version

Auto acceptance:
If event.acceptance_mode == auto:
    if capacity remains:
        application.status = accepted
        application.decided_at = now
        assignment = create_assignment_from_application(application)
    else:
        application.status = waitlisted
        application.decided_at = now
Else:
    application.status = pending
Manual acceptance:
Coordinator accepts application.
Set decided_by and decided_at.
Try create_assignment_from_application(application).
Assignment may be None if no post matches.

QR rules:
generate_qr_token returns raw token once.
DB stores only token_hash.
resolve_qr_token is public and does not consume token.
redeem_qr_token requires authenticated user and consumes token only on success.
Token validation:
exists,
not revoked,
not expired,
used_count < max_uses if max_uses exists.

QR redemption behavior:

purpose == checkin:
    check_in(user, event, user, method="qr_scan", qr_token=token)

purpose == walkin_registration:
    apply_to_event(user, event, source="qr_walkin", qr_token=token)

purpose == join_event:
    apply_to_event(user, event, source="invite")


Assignment creation:

create_assignment_from_application is the only place assignments are created.
It must also create Attendance(status="expected") if missing.
It must return None if no eligible post has capacity.

Post eligibility:

If post.required_skills is not empty:
    user.skills must overlap post.required_skills.

If post.physical_level == heavy:
    user.physical_ok must be True
    and user.can_lift_heavy must be True.

If post.physical_level == medium:
    user.physical_ok must be True.

If post.new_volunteers_allowed is False:
    user.new_to_volunteer must be False.


Auto assignment:

1. Lock event.
2. Get accepted applications without active assignment.
3. Get open posts ordered by priority ascending, id ascending.
4. For each application, choose first eligible post with remaining capacity.
5. Create assignment.
6. After assignments are created, build groups:
   - group by post,
   - group size = event.group_size,
   - group_code format: "G1", "G2", etc. per post.
7. Leader selection:
   - if post.leader_needed or event.leader_strategy == "first_experienced",
   - choose first member in group with has_leader_experience=True,
   - set is_group_leader=True.
8. Never create more than one leader per group.

Check-in rules:

Event must be active.
User must have active assignment for event.
If event.require_onboarding_ack is True:
    user must have acknowledged current event.onboarding_version.
If actor is the user:
    method must be qr_scan and QR token must be valid.
If actor is coordinator/admin:
    method may be coordinator_manual.
If already checked in, return existing attendance idempotently.

Checkout rules:
Attendance must be checked_in.
Set checkout_at = now.
Keep status checked_in until event completion, unless coordinator marks completed.

Feedback rules:
Event must be completed.
Score is required and must be 1..5.

coordinator_to_volunteer:
    rater must be event coordinator/admin.
    target_user required.
    target_user must have had active assignment in event.

volunteer_to_event:
    rater must have had active assignment in event.
    target_user must be None.

volunteer_to_coordinator:
    rater must have had active assignment in event.
    target_user is forced to event.coordinator_id.
