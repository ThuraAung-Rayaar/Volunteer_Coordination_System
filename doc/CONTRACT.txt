This file is the single source of truth.
Flash must treat this file as authoritative.

## 1. Stack

- Backend: Django + Django REST Framework
- Database: PostgreSQL
- ORM: Django models
- Migrations: Django migrations
- API docs: drf-spectacular
- Auth: phone OTP + DRF token
- Admin: Django admin
- Mobile later: React Native + Expo + TypeScript
- Mobile state: TanStack Query
- Mobile secure storage: expo-secure-store

## 12. QrToken

Fields:
- event
- created_by
- purpose
- token_hash
- max_uses
- used_count
- expires_at
- revoked_at

purpose:
- walkin_registration
- checkin
- join_event

Rules:
- Generate raw token with secrets.token_urlsafe().
- Store only token_hash.
- Return raw token once at generation time.
- used_count <= max_uses when max_uses is not null.
- Consume token atomically using select_for_update().
- Reject expired/revoked/over-used tokens.

## 21. Permissions

- App user can edit own profile only.
- App user can view own applications/assignments only.
- Only approved coordinator can create events.
- Only event coordinator or admin can publish/activate/complete/cancel.
- Only event coordinator or admin can accept/reject/waitlist applications.
- Only event coordinator or admin can run assignments or manual check-in.
- Volunteer can check in self if assignment confirmed and onboarding acknowledged.
- Only admin can moderate users/events/feedback.
- Only admin can view audit logs.

---

## 22. Auto-assignment rules

Deterministic rules only. No ML.

For each accepted application without an active assignment:
1. Find open posts with remaining capacity.
2. Filter by required_skills.
3. Filter by physical_level.
4. Filter new_volunteers_allowed.
5. Sort posts by priority.
6. Create Assignment with status = assigned.
7. If no suitable post, leave application accepted but unassigned.

Grouping:
- If group_size is set, create group_code values.
- If leader_needed and leader_strategy = first_experienced,
  choose a user with has_leader_experience.
- Only one active leader per group.
