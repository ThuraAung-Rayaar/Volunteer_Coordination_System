1. **Zero Python Recalculation (`W32`)**:
   - `users.verification_status` is never mutated directly in Python application code. Updates delegate authoritatively to PostgreSQL stored function `recompute_user_verification(p_user)` triggered by `trg_50_vimg_after`.
   - All 6 branches of the formula were directly validated: `none` (no current images), `rejected` (any current document rejected), `pending` (single approved document), and `verified` (`mock_selfie` paired with either `id_license` or `driver_license`).
2. **Database-Enforced Coordinator State Machine (`W34`–`W40`)**:
   - State machine transitions (`pending -> approved | revoked`, `approved <-> suspended`, terminal `revoked`) and approval prerequisites (`verified` active volunteer + active admin approver) are backstopped by `trg_01_coordinator_guard`.

   - Anti-self-review of identity images (`ck_verification_no_self_review`) and anti-self-approval of coordinator applications (`ck_coordinator_no_self_approval`) are enforced at presentation, service, and database constraint levels.
   - Private media streaming via [`AdminVerificationImageFileView`](file:///c:/Users/USER/Documents/INTERN/Project/Volunteer%20HR%20Management/python%20stack/backend/admin_portal/views.py#L61-L79) masks non-admin access with HTTP 404 (`ResourceMaskedNotFound`) and writes audit logs with `action="security.warning.admin_image_view"`.
